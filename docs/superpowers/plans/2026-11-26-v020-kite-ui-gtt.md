# 0.2.0 Part C: Kite-Style Watchlist and Instrument Sheet, GTT, Update Check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give v0.1.0 the Kite-style watchlist and draggable instrument sheet, add GTT orders (single and OCO) with full order safety, add the once-a-day GitHub update check, and move the Hermes budget to 6,000,000 bytes with gesture-handler and Reanimated installed properly.

**Architecture:**
- The watchlist model goes to version 2: groups, a sort per list, and list reordering. A version-1 document migrates on load, and the backup file goes to schema 2.
- The instrument sheet is a `transparentModal` route drawing its own `BottomSheet` on gesture-handler 3.3 (`usePanGesture`) and Reanimated 4.7. Depth is shared with the standalone depth screen through `DepthPanel`.
- GTT follows the order pattern:
  - pure wire format and reconcile in `src/market/gtt/`;
  - writes through `submitOrderAction`;
  - support detected from swagger or a probe, then from the first `gttorderbook` reply, keyed by broker and analyzer mode;
  - screens in `src/features/gtt/`.

**Tech Stack:** the v0.1.0 stack (Expo SDK 58, RN 0.88.1, TypeScript 6, TanStack Query 5, zustand 5, zod 4, jest-expo, Biome, dependency-cruiser, Maestro). Already in `package.json`, now used: react-native-gesture-handler ~3.3.0, react-native-reanimated 4.7.1, react-native-worklets 0.13.0 and expo-symbols.

**Spec:** `docs/superpowers/specs/2026-11-23-openalgo-mobile-phase1-design.md`, sections 17.1, 17.2, 17.3, 17.5 and 17.6, plus 5, 7.1, 7.5, 7.6, 7.10, 7.11, 9.2, 10 and 12.

**Depends on:** v0.1.0 as merged (`cdd0401`, plans `2026-11-24-m0-m1-foundation.md` and `2026-11-24-m2-trading-core.md`). The code is the ground truth for every existing name used here. Plans D (M3 chart), E (M4) and F (M5) come after this one, in that order.

   Expected: every one normalizes. An OCO's stop-loss is always the lower trigger with its own leg's price, so a modify prefill never swaps the stop-loss and the target. A row without a `trigger_id` is dropped and counted. Test: Task 6 **(RF 3)**.

## GTT contract (stock server, openalgo `c8b2896`)

**G1. Endpoints and versions.**
- `placegttorder`, `modifygttorder` and `cancelgttorder` use `ORDER_RATE_LIMIT`; `gttorderbook` uses `API_RATE_LIMIT`. All four exist from **2.0.0.8** (`ce0e4d591`; `restx_api/__init__.py:112-115`).
- The sandbox serves GTT from **2.0.1.9**. Before that, ANALYZE mode answers 501 `{"mode":"analyze","status":"error","message":"Sandbox GTT support not yet implemented"}` (`4890ccee9:services/gtt_orderbook_service.py:24-33`).
- `gttorderbook.status` (`active` by default, or `all`) exists from **2.0.2.4** (`bb89272ee`). Its schema has no `EXCLUDE`, so older servers answer 400 `{"status":"error","message":{"status":["Unknown field."]}}`.
- The place and modify schemas use `unknown = EXCLUDE` (`restx_api/schemas.py`: Place 437, Modify 506, `EXCLUDE` at 456-457 and 514-515; Cancel 564, Book 572-581).

**G2. Requests** (besides `apikey`):

- **place:** `strategy`, `trigger_type` (`SINGLE`|`OCO`), `exchange`, `symbol`, `action`, `product` (`CNC`|`NRML`; MIS gets a 400 "GTT supports only CNC (delivery) or NRML (overnight F&O); MIS is intraday-only."), `quantity` (> 0, whole outside CRYPTO), `pricetype` (`LIMIT` default | `MARKET`), `price` (required, ≥ 0), `triggerprice_sl`, `triggerprice_tg` (≥ 0, default 0), `stoploss`, `target` (OCO)
- **modify:** the same plus `trigger_id`; a full replacement
- **cancel:** `strategy`, `trigger_id`
- **book:** `status` (2.0.2.4+)

- **SINGLE** needs exactly one trigger above 0. A trigger above the LTP goes in `triggerprice_tg`, one below in `triggerprice_sl`, the other 0. The sandbox takes the fire direction from the field, on place and modify (`sandbox/gtt_manager.py:357-368`, `:471-472`), so a wrong field fires on the next tick.
- **OCO** needs all four values non-zero and `triggerprice_sl < triggerprice_tg`. Otherwise the reply is 400 `"{'triggerprice_sl': ['Stoploss trigger must be less than target trigger (triggerprice_tg).']}"`.
- The broker mappers ignore `price` for OCO (`broker/zerodha/mapping/gtt_data.py:36-75`, `broker/dhan/mapping/gtt_data.py:36-80`).

**G3. Replies.**
- **Success:** `{"status":"success","trigger_id":"…"}`. The sandbox adds `"mode":"analyze"` to write replies and to the book envelope, not to rows (`gtt_manager.py:651-656`).
- **Not active:** modify or cancel of a GTT that is no longer active → 404 `"No active GTT with trigger_id '…'"` (`gtt_manager.py:708-717`); live passes the broker's status through. This is not "unsupported".
- **Semi-Auto place:** queued, in either mode: `{"status":"success","message":"Order queued for approval in Action Center","mode":"semi_auto","pending_order_id":N}`.
- **Semi-Auto modify and cancel in LIVE:** 403 `"Modify GTT order is not allowed in Semi-Auto mode. Switch to Auto mode."` and `"Cancel GTT order is not allowed in Semi-Auto mode. Switch to Auto mode."`.
- **No GTT for the broker:** 501 `"GTT orders are not supported for broker '<b>' yet"`.
- **Other failures:** broker busy → 429; a broker exception → 500 `"Failed to place GTT due to internal error"`.

**G4. Book.** `{"status":"success","data":[{"trigger_id","trigger_type","status","symbol","exchange","trigger_prices":[…],"last_price","legs":[{"action","quantity","price","pricetype","product","triggered_order_id"?}],"created_at","updated_at","expires_at"}]}`. Active rows come first (`services/gtt_orderbook_service.py:20-33`).
- **`trigger_type`:** `single` or `two-leg` (Zerodha, Dhan, Angel, Upstox, the sandbox). Fyers falls back to `SINGLE`.
- **Statuses:** active, triggered, disabled, expired, cancelled, rejected, deleted, or the broker's own word.
- **Leg order:** Zerodha lists the legs in ascending trigger order (`[stoploss, target]`); other brokers do not promise an order.

**G5. Brokers with GTT.** Zerodha and Dhan from 2.0.0.8; Angel, Fyers and Upstox from 2.0.2.2; at `c8b2896` also Pocketful and Rupeezy. Every other broker answers 501.
