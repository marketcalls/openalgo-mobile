# 0.2.0 part F (M5): Tools part 2 and the 0.2.0 release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All 20 tools on an unmodified OpenAlgo ≥ 2.0.0.0. Plan F adds:
- the last eight DOM pages, with their session routes answered on the phone at golden parity with the server's Python;
- native multi-leg basket review for Strategy Builder and a native Arbitrage scanner;
- a device-local Strategy Portfolio, included in the backup;
- the 0.2.0 release.

**Architecture:**
- **Routes** (`src/dom/routes/`): one module per session route on E's `RouteDeps`; history through `fetchHistoryBatch`. OI Profile answers early and finishes in the background into a previous-day-OI cache.
- **DOM** (`src/dom/tools/`): entries Option (E's six + Strike Profile, OI Profile), Series (openalgo-charts pages), Vol Surface (Plotly 3D, heatmap fallback) and Strategy (Builder, Portfolio). Navigation that leaves an entry goes to native.
- **Orders:** baskets parse strictly, get a native review, go once, match per leg and reconcile against the order book; shared by E's held writes and native Arbitrage.
- **Native Arbitrage** (`src/features/arbitrage/`): universe from the master; Depth on visible rows only; a `multiquotes` ranking snapshot.

**Tech Stack:** v0.1.0 + plans C, D and E; no new package (`plotly.js/lib/heatmap` is in E's pinned `plotly.js` 3.3.1). Python goldens: uv 0.11.3, the server's `uv.lock`, E's harness.

**Spec:** `docs/superpowers/specs/2026-11-23-openalgo-mobile-phase1-design.md`: 7.7, 7.8 (Strike Profile through Strategy Portfolio rows), 7.10 (baskets), 7.5, 7.6, 9.2, 9.3, 10, 11 (M5), 12, 17.4, 17.6.

**Depends on:** v0.1.0 and plans C, D and E, implemented; their code is the ground truth for every name. F uses E's "Interfaces exported for plan F" as exported, D's `Route`/`createRequestRouter`/`fromApiError`/`createWsEmulation`/`HistoryRow`/`IntervalsSchema`/`fitBackup`, and C's `RESTORABLE` and version note.

## Global Constraints

- **Server.** Only `/api/v1` and the WebSocket proxy; every session route is answered on the phone, none is sent. The DOM holds `NATIVE_KEY`, never the key, the URL or a socket.
- **Frontend is read-only.** Pages are imported unchanged. Types come from `@/api/*` with `import type`, only in `src/dom/routes/`.
- **Branch and commits.** Work on `phase1/v0.2.0` after plan E. Commit, never push: a push, PR, merge, tag or release happens only in T18 Step 7, each with the owner's explicit approval. Every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No local native builds.** No prebuild, gradle or xcodebuild. Maestro runs in CI only.
- **Colours.** BUY is green `tokens.trade[scheme].buy` (`#00a63e`) and SELL red `.sell` (`#e7000b`) on every native leg, button and row.
- **Budgets.**
  - Hermes android/ios 6,000,000; chart DOM 2,330,000; every tool DOM page 1,900,000 bytes of JS.
  - 5% growth per PR; T14 and T18 rebaseline with a reason. A budget is never raised.
- **Order safety** (design 7.10, M2 rulings 3 and 5) binds every basket:
  - review first; the mode re-read before the send; biometrics when `confirmLiveWrites` is on and the mode is live;
  - `useSubmitGuard`; `NEW_ORDER` held until the outcome is known; sent once, never retried;
  - `MaybePlaced`, a `basketorder` Server error and `no_id` are reconciled against the order book, never re-sent;
  - a reply without the sandbox tag after an ANALYZE review is the danger notice.
- **Strategy tags.** A held basket keeps the page's `strategy`; native Arbitrage sends `'calendar_arbitrage'`, as the web does.
- **History** goes through the history lane only: ≤ 3 in flight, ≤ 3/s. A screen that is hidden calls nothing.
- **Golden parity.** Rounded fields match exactly. Python `round` is `pyRound`, `sum()` of floats `pySum`, `+=` loops plain addition in the server's order. The only tolerances are those a task names.
- **Real test server.** Only through controller scripts in market hours (09:15–15:30 IST). Nothing prints the key.
- **testIDs** are the Maestro contract (`e2e/README.md`; `{X}` is `[A-Z0-9&_-]`). "→ FAIL": the module is missing. "→ PASS": every test in the command passes.

## Review Focus

1. **A basket whose reply never comes (timeout, 502) or whose legs partly fail.**
   - Expected: each leg is checked against the order book by symbol, exchange, action, product and quantity, ignoring ids known at review. Partial results show per leg, with "View in order book". Nothing is re-sent.
   - Test: T9, T10 **(RF 1)**.
2. **The user leaves Strategy Builder, or the app goes to the background, with a basket review open or sending.**
   - Expected: an unconfirmed basket is answered "cancelled" and never sent later. A begun send keeps its real outcome, shown as a toast, and `NEW_ORDER` holds until it is known.
   - Test: T10 **(RF 2)**.
3. **OI Profile's first load of the day is cut short** (the tool is closed, or the broker answers 429s).
   - Expected: the load stops with the tool, only finished legs are cached, and reopening fetches only the missing ones. A refresh after a full load costs 2 calls.
   - Test: T5 **(RF 3)**.
4. **A server older than 2.0.2.0** (no `with_greeks`, `expiry_ts`, `forward_price` or `underlying_symbol`).
   - Expected: Strike Profile and Strategy Builder get Greeks from E's on-device `with_greeks` mode. Option Greeks, Straddle and the strategy charts find the underlying through the index map, or the MCX near-month future.
   - Test: T4, T5, T7, T15 **(RF 4)**.
5. **Arbitrage's universe of about 900 futures, while other screens hold subscriptions.**
   - Expected: only visible rows' legs are held, at most 200 symbols, within the app's 500. Fast scrolling releases off-screen holds. Polling mode polls only the visible rows.
   - Test: T13 **(RF 5)**.
6. **A DOM tool in polling mode.** `MarketDataManager` falls back after 3 failures and a clean close, else only after 10 reconnects (~181 s; `MarketDataManager.ts:441-467`).
   - Expected: the first `multiquotes` within 6 s. Test: T12, T16 **(RF 6)**.
