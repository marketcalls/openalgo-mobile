# 0.2.0 part D (M3): Chart Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The chart for an unmodified OpenAlgo ≥ 2.0.0.0: openalgo-charts in an Expo DOM component behind a key-free typed bridge, with app-socket ticks, a `/api/v1` session calendar, all built-in indicators, drawings on the phone, and on-chart trading as intents to the native order flows; plus the DOM foundation (bridge, host, socket emulation, CSP, env seeding, chunk workaround) that plan E reuses.

**Architecture:**
- **`src/dom/bridge/`**: `protocol.ts` (versioned zod messages, the only file both runtimes import), the native `DomHost` and `outbox`.
- **`src/dom/web/`**: what every DOM bundle loads first: env seeding, CSP, link guard, and the DOM side of the bridge.
- **`src/dom/gateway/`** (native): request router, the chart's two-route allowlist, DOM storage, and the WebSocket emulation over the app's socket.
- **`src/dom/chart/`** (DOM): `ChartDom.tsx` ('use dom') with `createWidget` and about 400 lines of glue ported from `frontend/src/lib/trading/terminal.ts`.
- **Native:** `src/market/chart/` (calendar, intervals, book-to-line mapping, price actions) and `src/features/chart/` (screen, intents, one-tap).
- The DOM places nothing: every action is a `ChartIntent` that native turns into the M2 ticket, modify, cancel or close flow.

**Tech Stack:** As shipped in v0.1.0 + plan C, plus `openalgo-charts` **2.7.3** (exact), `react-native-web` and `@expo/metro-runtime` (`npx expo install`), and `@expo/dom-webview` (already present through expo).

**Spec:** `docs/superpowers/specs/2026-11-23-openalgo-mobile-phase1-design.md`: 7.9 (chart), 7.7 (bridge: what the chart needs), 7.5, 7.6, 7.10, 7.11, 9.2, 10, 12, 17.4, 17.6.

**Depends on:**
- `2026-11-24-m0-m1-foundation.md` and `2026-11-24-m2-trading-core.md` as implemented (their code is the ground truth for every existing name), and plan C (Kite UI + GTT), done.
- Tasks are T1–T18. "E" is plan E (M4), which consumes **Interfaces exported for plan E**.

## Global Constraints

- **Server.** Only `/api/v1` (key in the JSON body, added by `HttpClient`) and the WebSocket proxy. No session route is ever called: the DOM's calls are answered by native (design 7.7).
- **The WebView never holds the real key, the server URL or a socket.** The DOM uses the placeholder `'__native__'` and the URL `wss://native.invalid/ws`.
- **Branch and commits:**
  - work on `phase1/v0.2.0`, after plan C; commit, never push (the controller pushes for CI);
  - every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No local native builds** (no `expo prebuild`, gradle or xcodebuild). Local checks are T18 Step 1's and the mock server; Maestro runs only in CI.
- **Colours.** BUY green and SELL red everywhere: `tokens.trade[scheme].buy` `#00a63e` and `.sell` `#e7000b`; candles up = buy colour, down = sell colour.
- **Budgets** (design 12, 17.6), checked per PR with 5% growth:
  - Hermes: `bundle-baseline.json` limits `android`/`ios` 6,000,000 bytes;
  - chart DOM: 2,330,000 bytes of JS; tool DOM: 1,900,000.
  - A chart screen: about 8 calls at load and about 4/min steady.
  - Chart forming bar in polling mode: 2 s home / 5 s tunnel, through T5's `quotes` consumer (`POLL_RATES.quotes`; `chartLtp` has the same values and stays unused).
- **Order safety** (design 7.10 + M2 rulings) for every chart-originated write:
  - review or confirm first; in one-tap mode the header's ModeBadge stands for the review;
  - mode re-read before send (`submitOrderAction`), biometrics when `confirmLiveWrites` is on and the mode is live;
  - one request in flight plus a 120 ms cooldown (`useSubmitGuard`);
  - sent once, never retried; MaybePlaced and `no_id` are reconciled, never re-sent.
- **Strategy tags:** `'mobile'` for tickets, `'mobile-chart'` for writes that start on the chart.
- **Version pin.** `openalgo-charts` equals the frontend's pin, `frontend/package.json:62` at `openalgo.ref` `c8b2896`: 2.7.3. The eager-chunk list is tied to it.
- **Real test server.** Steps that need it are scripts the controller runs (`npm run real-server-check`); nothing prints the key.
- **Performance bars** (chart open ≤ 2.5 s, pan ≥ 30 fps) are measured at the 0.2.0 device test, not in CI. The chart logs its open time.
- **testIDs** named in tasks are the Maestro contract (`e2e/README.md`). "→ FAIL": the module is missing; "→ PASS": every test in the command passes.

## Review Focus

1. **The widget's symbol box changes the instrument while an intent is in flight** (search, then a fast BUY). Expected: native acts only on intents for the current instrument; others get "The chart was changing symbol. Try again." and open nothing. Test: T13 **(RF 1)**.
2. **A dragged or X'd order line belongs to an order that just filled or was cancelled.** Expected: native reads the book fresh; a gone order shows "This order is no longer open." and the lines are pushed again. No modify or cancel opens. Test: T13 **(RF 2)**.
3. **The OS kills the WebView's render process** (memory pressure). Expected: no blank screen; the host detaches, the emulation releases the dead page's holds, and the screen shows "The chart was closed to free memory." with Reload. Test: T3, T14 **(RF 3)**.
4. **The app locks, the server sends 1012, or the feed reconnects with the chart open.** Expected: the DOM's socket stays open, its holds survive, and ticks resume without a reload. Test: T5 **(RF 4)**.
5. **A chart opened outside market hours, or on a symbol another screen streamed.** Expected: no candle from a stored or seed quote; only ticks after the subscribe are sent. Test: T5 **(RF 5)**.
6. **A dragged order line whose modify never happens** (sheet dismissed, confirm declined, mode change, Semi-Auto 403, refusal). Expected: the line returns to the book price at drag end, moves only on a `chart.orders` push, and is redrawn on refocus. Test: T12, T14 **(RF 6)**.

## Chart contract (checked in code)

**K1. openalgo-charts 2.7.3** (`node_modules/openalgo-charts/dist/*.d.ts`):
- `createWidget(container, WidgetOptions)` (`widget/index.d.ts:3225`); the options used are those T11's `widgetOptions` sets.
- `OpenAlgoDataFeed` calls only `POST ${baseUrl}/api/v1/history` and `/search`. It needs `res.ok`, `res.status` and `res.json()`, and maps `1d→D`, `1w→W`.
- `OpenAlgoLiveDataFeed(OpenAlgoLiveConfig)` = REST + `OpenAlgoWsFeed` + candle builder: `subscribeBars` (LTP), `subscribeDepth`, `socketFactory`, `timezone`.
- `withBarCache` forwards `subscribeBars` and `searchSymbols`.
- **The socket:**
  - `SocketLike.onclose` carries no code;
  - nothing but `authenticate` is sent until `{type:'auth',status:'success'}` arrives (5 s ack timeout);
  - after 45 s of silence it sends `{action:'ping'}` and needs a frame within 5 s;
  - a frame whose `data.depth.buy/sell` is present is a depth event, otherwise `data.ltp` is an LTP event;
  - tick time comes from `last_trade_time | ltt | exchange_timestamp | timestamp`, else now.
- **Storage.** `AsyncStorageLike {entries(prefix), getItem?, setItem, removeItem, journal?}`. Keys start `STORAGE_PREFIX` `'oac-widget:'` plus the namespace. Drawings sit under `DRAWINGS_KEY_PREFIX` `'drawings:'` plus `EX:SYM`.
- **Registries after importing `/indicators` and `/transform`:**
  - 112 indicators;
  - chart types `candlestick hollow-candle volume-candle bar high-low line line-markers step area hlc-area baseline column histogram point-figure kagi`;
  - transforms `heikin-ashi renko range-bars line-break point-figure kagi`;
  - `isKnownInterval`: `D` and `W` true, `M` false.
- **The widget has 8 lazy chunks** (`openalgo-charts.widget.*-<hash>.mjs`).
- **Chart API:** `TOPBAR_HEIGHT`, `chart.coordinateToPrice(y, pane)`, `subscribeDrag`, `subscribeClick`, `addPriceLine` (a `closeButton` click reports `<id>::close`), `widget.draw.activeTool()`, `widget.on('symbol', …)`, `roundToTick`.

**K2. Server calendar:**
- `market/timings {date:'YYYY-MM-DD'}` returns `data[{exchange,start_time,end_time}]` in epoch ms (`database/market_calendar_db.py:665-760`). Normal, settlement and weekend rows are built from a **naive midnight in the server's time zone**; holiday and special-session rows are stored absolute epochs (`:104-105, 686-699`):
  - a weekend lists only CRYPTO;
  - a holiday lists only the open exchanges (or none);
  - the defaults are `:57-73` (NSE/BSE 09:15–15:30, NFO/BFO 09:15–15:40, CDS/BCD 09:00–17:00, MCX/NCO 09:00–23:55, CRYPTO all day).
- `market/holidays {year}` returns `data[{date, holiday_type, closed_exchanges[], open_exchanges[{exchange,start_time,end_time}]}]`.
- `intervals {}` returns `data{seconds,minutes,hours,days,weeks,months}`.
- All three predate 2.0.0.0 (`f67825c03`, 2025-12-18).

### Task 3: DomHost and outbox (native)

**Files:**
- Create: `src/dom/bridge/outbox.ts`, `src/dom/bridge/DomHost.tsx`, `src/dom/bridge/domHost.test.tsx`

**Interfaces:**
- Consumes: T2 protocol (`JSONValue` included); `log` (`core/log/logger`); `Linking` (react-native); `DOMProps`, `DOMImperativeFactory` from `expo/dom`.
- Produces:
```ts
export type Outbox = { post(m: NativeToDom): void; attach(deliver: (batch: NativeToDom[]) => void): void;
  detach(): void; clear(): void; stats(): { queued: number; dropped: number } }   // clear drops the queue
export function createOutbox(o?: { schedule?: (fn: () => void) => void; maxQueue?: number; maxBatch?: number }): Outbox
  // defaults: requestAnimationFrame, 2000 (drop oldest, count), 256 per deliver
// DomHandle and DomEntryProps come from protocol.ts (T2)
export type DomHandlers = {
  request?: (r: DomRequest, signal: AbortSignal) => Promise<DomReply>; socket?: (m: DomSocketMsg) => void
  storage?: (m: DomStorageMsg) => Promise<DomReply>; intent?: (m: DomIntentMsg) => void; event?: (e: DomEvent) => void }
export const REFUSED_REPLY: DomReply      // { status: 400, body: { status: 'error', message: 'Refused by the app' } }
export const ACCEPTED_REPLY: DomReply     // { status: 202, body: null }
export function DomHost<P extends object>(p: { Dom: ComponentType<P & DomEntryProps>; props: P; handlers: DomHandlers;
  outbox: Outbox; webview?: Partial<DOMProps>; testID: string; onGone: () => void }): JSX.Element
```
- **Behaviour:**
  - `bridge` is stable and validates every message with `DomToNativeSchema`; an invalid one, or a kind with no handler, gets `REFUSED_REPLY` and at most one `log.warn('dom', 'refused <kind>')` per 10 s, never the payload.
  - Each `request` gets its own `AbortController`; an `abort` with its `rid` aborts it (and gets `ACCEPTED_REPLY`).
  - `event 'loaded'` calls `outbox.attach(b => ref.current?.deliver(b))` before it reaches `handlers.event`.
  - `event 'link'` opens only an `https:` URL, with `Linking.openURL`.
  - `onRenderProcessGone` / `onContentProcessDidTerminate` call `outbox.detach()` and then `onGone()`.
  - The host is wrapped in `memo`. On a remount (a new `key`) it sets `ref.current = null` first (spike `CHANGES.chart.md` §9).
  - WebView defaults: `scrollEnabled:false`, `bounces:false`, `overScrollMode:'never'`, `matchContents:false`, `unstable_useExpoModulesBridge:false`, `webviewDebuggingEnabled:__DEV__`.
  - Design 7.7's origin and file-access limits cannot be set: `@expo/dom-webview` ignores `originWhitelist` and `allowFileAccess*`, file access always on (`DomWebView.types.d.ts:222-236`). The CSP and link guard carry it; T18 checks on device.

- **The protocol emulated, per `sid`:**
  - **`open`.** A URL other than `DOM_WS_URL` closes at once. Under `whenPolling 'fail'`, a polling feed closes it at once and a live feed turning polling closes it then. Otherwise it gets `open`.
  - **`authenticate` / `auth`**, whatever key: `{type:'auth',status:'success',message:'Authentication successful',broker,user_id:null}`.
  - **Before auth**, every other action gets `{status:'error',code:'NOT_AUTHENTICATED',message}`.
  - **`subscribe`** (a `symbols[]` list or one pair; mode `1|2|3`, `LTP|Quote|Depth` in any case; `depth` or `depth_level`, default 5):
    - each valid pair calls `realtime.acquire({exchange,symbol,mode,depth})`;
    - under `'relay'` it also calls `polling.register({kind:'quotes',keys:()=>[key]}, d.active)`;
    - then `store.subscribe(key)`;
    - the ack is `{type:'subscribe',status:'success'|'partial',subscriptions:[{symbol,exchange,status,mode:'LTP'|'Quote'|'Depth',depth?,broker}],message,broker}`;
    - an invalid exchange, an over-long symbol, or a pair past `MAX_DOM_SYMBOLS` is an error entry.
  - **Holds are keyed `${key}|${mode}`** (the chart holds modes 1 and 3 on one symbol). **`unsubscribe`** releases the named mode only (no mode: all of the pair's); **`unsubscribe_all`**, all. Ack `{type:'unsubscribe',status:'success',successful,failed:[]}`.
  - **`subscribe_orders`** acks and forwards every bus `OrderUpdate` as `{type:'order_update',…server field names}`.
  - **`ping`** → `{type:'pong',status:'success',server_timestamp}`. It is never sent upstream.
  - **Anything else** → `INVALID_ACTION`; non-JSON → `INVALID_JSON`.
- **Ticks.** A store flush for a key gives one `market_data` frame per subscriber: `{type:'market_data',symbol,exchange,mode,broker,data}`.
  - mode 1: `{ltp}`;
  - mode 2: ltp, open, high, low, close, volume, oi, average_price, bid, ask;
  - mode 3: ltp plus `depth{buy,sell}` (price, quantity, orders) and the totals, only when the quote has a book. Under polling (no book in `multiquotes`): `ltp` plus `depth:{buy:[],sell:[]}`, still a depth event to the library (`sd`), so the panel gets the LTP.
  - Absent fields are omitted. Only quotes with `source !== 'seed'` and `ts ≥` the subscription time are sent.
- **Holds and closes.** Holds live until unsubscribe, close or `closeAll()`; a lock, a 1012 or a reconnect never closes the DOM socket.
